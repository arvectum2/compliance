# Arvectum Compliance — дорожная карта

Инициирована 2026-11-05. Статус разработки проверяется по критериям
приёмки каждого этапа, а не по наличию документации.

- AC-00. Foundation: GitHub/GitVerse/Mac mini, правила синхронизации,
  спецификация архитектуры и интерфейсов, политика безопасности. Выполнено (foundation).
- AC-01. Сканер на Data Platform: формы, DOM, cookies, браузерные
  сетевые события, ограниченный и безопасный обход. Частично (Feature 001: статический сканер + CLI + Data Platform; cookies/JS — Feature 002).
- AC-02. Версионированные правила 152-ФЗ, доказательства, фиксированные
  юридические источники, тестовые кейсы, ручная проверка выводов. Не начат.
- AC-03. Внутренний MVP: организации, домены, API, история, PDF. Не начат.
- AC-04. Коммерческий MVP: тарифы, биллинг, внешние пилоты. Не начат.
- AC-05. Мониторинг изменений, уведомления, проверки в CI. Не начат.
- AC-06. Создание исправляющих Pull Request после разрешения владельца
  и повторная проверка результата. Не начат.
- AC-07. White-label и дополнительные версии нормативных пакетов. Бэклог.

## Принципы реализации

1. Data Platform не содержит специализированных правил 152-ФЗ.
2. Compliance Core не зависит от SaaS и платежных провайдеров.
3. Результаты имеют код правила, версию, свидетельство и уровень уверенности.
4. Проверка извне не объявляется подтверждением полного соответствия.
5. Изменения на сайтах только по подтверждённым правам и с одобрением.
6. Серверный обход ограничен и устойчив к SSRF/внутренним адресам.
7. SDK/API/CLI доступны внутренним продуктам без SaaS-подписки.

## AC-00 acceptance gate

с доказательством на TCP:443 при включённой/отключённой политике — готов.
EG-003b: фактический HTTPS gateway service в этом namespace ещё не
размещён; production browser LIVE и SaaS остаются NO-GO.

## EG-003b (внутренний срез)
Выполнен EG-003b1: HTTPS Python GatewaySession исполняется в отдельном
`nftables` контейнере; Chromium без сети взаимодействует с ним по stdio.
3 синтетических E2E + негативные проверки. Вручную выполнен первый
`arvectum.com` browser smoke (только GET главной страницы, HTTP 200).
EG-003b2 (настоящее DNS proof, auth/RBAC, IPv6/DNS security review,
subresource/redirect isolation) остаётся блокером публичного SaaS.

## EG-003b2 — управление организациями и проверкой DNS
Подготовлен внутренний контрольный контур: private tenant RBAC,
256-bit токены только в хешированном виде, SQLite rate limits,
настоящая проверка TXT через HTTPS (Cloudflare + Google), подписанный
`gateway-v2` с ограничением статических субресурсов и локальный
операторский CLI. Запрос реального DNS arvectum.com пока возвращает
отсутствие опубликованного challenge — доступ не выдан.
Публичная регистрация организаций, защищённая доставка grant в gateway
и независимый аудит остаются NO-GO.


## EG-003b2b — защищённый gateway handoff
Выполнен тестовый Ed25519 handoff: host проверяет HMAC grant и отзыв
права перед каждым запросом, контейнер проверяет lease/permit с
публичным ключом, подпись привязана к URL, типу ресурса, номеру
запроса и TTL 3 секунды. Пройдены двухконтейнерные сценарии отзыва
во время задания и подмены подписи на synthetic .invalid fixtures.
В продуктивном контуре остаются невыполненными: подключение реального
DNS-верифицированного tenant, централизованное управление ключами
и независимый сетевой аудит.


## EG-003b2c — реальный DNS gate и постоянные ключи
Реализован persistent Ed25519 в каталоге 0700, без авто-ротации.
Подтверждение домена сохраняет происхождение: `doh-quorum`,
`offline-test`, `legacy`; только реальное dual-DoH proof разрешает
внутренний `verified-root` HTTPS smoke в изолированном nftables-
контейнере. HTML не сохраняется. Публичный браузерный SaaS
остаётся NO-GO до настоящего DNS и независимого аудита.

## EG-003b2d — ротация signing keys и IPv6 deny-control
Реализована атомарная локальная Ed25519 ротация с версиями ключей,
общей блокировкой на время `verified-root` и explicit crash recovery,
без молчаливой смены активной идентичности. Добавлен независимый
ядровый IPv6 тест: TCP ::1:443 доступен без nftables, блокируется с ним.
KMS/HSM и распределённая координация остаются NO-GO для SaaS.

## EG-002b2a — защита от подмены подтверждения домена
При завершении задания hostname и proof сверяются с записью SQLite,
а не только с полями Claim от воркера. Подстановка другого действующего
proof не обходит отзыв исходного домена. Негативный offline-тест пройден.
Атомарная межбазовая отмена и production worker остаются NO-GO.

## EG-002b3a — offline сверка отзыва разрешений
Добавлена явная `reconcile_revocations`: пакетная проверка активных
заданий по локальному DNS proof registry, перевод отозванных в `denied`,
аннулирование lease и запись обезличенного события. Негативные тесты
для queued/running, повторного вызова и ограниченного пакета.
Ограничения: сканирование с начала очереди может голодать на здоровом
префиксе; нет атомарности между двумя SQLite и нет распределённого
барьера отзыва. Production worker и публичный SaaS остаются NO-GO.


## EG-002b3b1 — справедливый обход отозванных разрешений
Добавлен сохраняемый в SQLite курсор обхода активных заданий с
лексикографическим порядком и переходом в начало очереди. Ограниченный
пакет не застревает на неизменном здоровом префиксе; курсор переживает
перезапуск. Проверено offline. Это **не** атомарный барьер между
двумя SQLite, не распределённая очередь и не production worker.
Публичный SaaS по-прежнему NO-GO.


## EG-002b3b1a — контроль связности proof и hostname
При выдаче lease, завершении и сверке отзыва сверяется не только
состояние DNS proof, но и его hostname с записью задания. При
расхождении задание запрещается и lease аннулируется; добавлены
негативные offline-тесты повреждённых записей. Межбазовая атомарность
и независимая идентификация воркеров по-прежнему NO-GO для SaaS.


## EG-002b3b1b — единый снимок DNS-подтверждения
Проверка статуса, метода dual-DoH, срока и hostname теперь выполняется
одним SQL SELECT для enqueue, claim, finish и reconcile. Устранён
промежуток между двумя чтениями proof registry; добавлен отказ при
несоответствии hostname ещё до постановки в очередь. Это не устраняет
межбазовую гонку с отзывом, поэтому distributed revocation и
production worker остаются NO-GO.

## EG-002b3b2a — ограничение фоновой очистки lease
Введён пакетный `expire_batch(limit=500)`: за один вызов не более
500 переходов в `expired`. Квота активных заданий и сверка отзыва
не учитывают уже истёкшие lease даже до физического обновления строки.
Добавлены offline-тесты повторных партий, квоты и просроченного
running-задания. Межбазовая атомарность, distributed barrier и
production worker остаются PUBLIC NO-GO.


## EG-002b3b2b — bounded claim-time revocation

Устранён неограниченный цикл при выдаче задания: если перед здоровым
заданием находится большой FIFO-префикс с отозванным DNS proof, один
вызов `claim` отклоняет не более 100 записей (лимит 1–1000) и
возвращает None. Следующий вызов продолжает работу, события не
дублируются. Проверено offline; cross-store atomicity и
distributed worker identity остаются PUBLIC NO-GO.


## EG-002b3b2c — индексы для ограниченной SQLite-очереди
Добавлены индексы по срокам истечения queued/running, активной
квоте tenant и времени очистки терминальных заданий. Проверено
повторное открытие SQLite и использование индексов планировщиком
для выборок истечения. Не меняет семантику lease, DNS proof или
межбазовую атомарность; PUBLIC NO-GO сохраняется.

## EG-002b3b2d — локальный read-only аудит очереди
Добавлена диагностическая проверка целостности SQLite, структуры
lease и терминальных результатов, без записи данных и раскрытия
токенов. Возвращаются только агрегаты и признак полноты обхода;
неполная проверка или аномалии означают NO-GO для будущего worker
startup. Это не production startup gate, не cross-store atomicity и
не независимая идентификация воркеров.


## EG-002b3b2e — расширенный контроль целостности очереди
Read-only preflight дополнен проверкой каноничности hostname,
идентификаторов tenant/job/proof, SHA-256 подписи grant, полей worker
в очереди и хронологии lease. Негативные offline-тесты добавлены.
Это не аутентификация воркера и не атомарный отзыв между базами.
Публичный SaaS остаётся NO-GO.

## EG-002b3b2f — сверка журнала событий
Локальный ограниченный read-only аудит проверяет последнее событие
каждого задания: его состояние и время должны совпадать с записью
очереди. Отсутствие события и подмена состояния/времени выявляются
offline-тестами. Полная история и межбазовая атомарность не доказаны;
публичный SaaS остаётся NO-GO.

## EG-002b3b2g — обнаружение осиротевших событий
Read-only аудит выявляет запись журнала событий без соответствующего
задания даже вне ограниченной выборки jobs. Добавлен offline-тест с
отключённым FK для моделирования повреждения. Это не проверка всей
истории и не межбазовая атомарность; публичный SaaS остаётся NO-GO.


## EG-002b3b2h — проверка исторических событий (offline)
Read-only аудит обнаруживает некорректные состояния и временные метки
событий за пределами интервала жизни задания, в том числе вне
ограниченной выборки jobs. Это не полная проверка переходов состояний
и не межбазовый барьер отзыва. Публичный SaaS остаётся NO-GO.


## EG-002b3b2i — порядок журнала событий (offline)
Read-only аудит проверяет, что первая запись истории каждого задания
имеет состояние queued и что время событий не убывает в порядке вставки.
Добавлены негативные тесты подмены истории. Проверка не доказывает
полноту допустимых переходов, межбазовую атомарность или подлинность
воркера. Публичный SaaS остаётся NO-GO.

## EG-002b3b2j — допустимые переходы журнала (offline)
Read-only аудит теперь выявляет недопустимые переходы состояний и
повторное оживление терминальных заданий. Добавлены негативные тесты.
Подлинность событий и межбазовая атомарность не доказаны; SaaS NO-GO.

## EG-002b3b2k — отсутствующая история за пределами выборки
Read-only preflight выявляет задания без событий журнала даже за пределами
ограниченного сканирования jobs. Добавлен негативный offline-тест.
Это не доказательство подлинности журнала или межбазовой атомарности;
публичный SaaS остаётся NO-GO.

## EG-002b3b2l — сверка последнего события вне выборки
Read-only аудит выявляет расхождение последнего события и состояния/времени
задания даже за пределами ограниченной детальной выборки. Добавлен
негативный offline-тест. Межбазовая атомарность и подлинность событий
не доказаны; публичный SaaS остаётся NO-GO.

## EG-002b3b2m — digest вне ограниченной выборки
Read-only аудит теперь выявляет некорректный SHA-256 grant_digest также
за пределами детального сканирования jobs. Добавлен негативный offline-тест.
Это не подтверждение подлинности grant и не межбазовый барьер отзыва;
публичный SaaS остаётся NO-GO.

## EG-002b3b2n — идентификаторы за пределами выборки

Read-only аудит проверяет каноничность tenant/job/proof/hostname также
за пределами детальной выборки. При аномалии будущий worker должен
отказать в запуске. Проверка хвоста может быть дорогой на большой БД;
это offline preflight, не распределённая авторизация. SaaS — NO-GO.

## EG-002b3b2o — метаданные заданий вне выборки

Offline read-only аудит обнаруживает некорректные worker/lease/result и
временные поля также за пределами ограниченной выборки jobs. Проверка
не является производственным барьером отзыва или аутентификацией воркера.
Публичный SaaS — NO-GO.

## EG-002b3b2p — проверка курсора reconciliation (offline)

Read-only аудит выявляет неизвестные имена курсоров, некорректные
временные метки и идентификаторы в maintenance_cursor. Проверка
не заменяет распределённый барьер отзыва и проверку личности воркера.
Публичный SaaS — NO-GO.

## EG-002b3b2q — согласованный снимок offline-аудита

Read-only проверка целостности JobLedger выполняется в явной SQLite
транзакции чтения, чтобы параллельные изменения очереди и журнала не
давали несогласованные результаты разных запросов. Тест проверяет начало
транзакции до чтения и отсутствие записей. Это локальный снимок одной БД,
не межбазовая атомарность или распределённый барьер. PUBLIC NO-GO.

## EG-002b3b2r — неизменность времени постановки в очередь (offline)

Read-only аудит требует совпадения времени события `queued` с временем
создания задания, даже если обе записи остаются в допустимом временном
интервале. Добавлен негативный offline-тест. Проверка не удостоверяет
подлинность журнала и не обеспечивает межбазовую атомарность. PUBLIC NO-GO.

## EG-002b3b2s — локальный операторский preflight

`arvectum-compliance-admin --state-dir <private-dir> ledger-audit`
проверяет существующий `jobs.db` без создания БД, ключей или схемы.
Возвращает только агрегаты, `gate=PASS` (код 0) либо `NO-GO`
(код 3 при аномалии/неполной проверке); ошибки конфигурации — код 2.
Проверка только offline: не запускает worker и не заменяет распределённый
барьер отзыва, независимую идентификацию и аудит. PUBLIC NO-GO.
