# Arvectum Compliance — инженерная конституция Spec Kit

Версия 1.0.0 · 2026-11-05 · Spec Kit CLI 1.2.4 · integration none.

## Обязательные правила
1. **Evidence first:** найденный факт содержит rule_id, версию правила, URL, минимальное доказательство и классификацию уверенности. Нельзя подменять эвристическое наблюдение юридическим заключением.
2. **Безопасный сбор:** активные проверки только явно разрешённых ресурсов; запрет локальных/частных сетей и credential-bearing URL, проверки каждого redirect; resource caps, отсутствие POST-запросов и отправки форм. Контроль DNS-rebinding/egress вынести в обязательный production gate.
3. **Data Platform — единственное общее ядро:** клиентские интеграции через её контракт; не дублировать код обхода/поиска/хранения, не импортировать код Tender Agent.
4. **Разделение ответственности:** core правил не зависит от SaaS, биллинга и транспорта; интеграционные адаптеры отделены; правила с датами действия и версиями.
5. **Приёмка по тестам:** каждая спецификация имеет acceptance criteria, negatives, трассировку задач и тесты; завершение отмечается только после проверки.
6. **Данные и секреты:** отсутствие токенов, персональных данных и клиентских материалов в git/логах; локальный и CI режимы без необходимости внешней сети.
7. **Изменения:** только управляемые PR и CI; зеркалом GitVerse управляет GitHub, не делать прямых коммитов в GitVerse. Никаких изменений чужих сайтов без отдельного разрешения.

## Источники требований
Product ROADMAP и утверждённые пользователем цели → specs/<feature>/spec.md → plan.md → tasks.md → код и проверки. Нормативные утверждения требуют первоисточника и юридической валидации; разработка не сертифицирует соответствие 152-ФЗ.
